# СтройМаркет: лечение legacy-магазина образца 2014 года

Демо-проект. Типичный интернет-магазин, написанный в 2014 году и с тех пор
не обновлявшийся: медленный каталог, дыры в безопасности, пароли открытым
текстом. Задача — вылечить его, не меняя дизайн и не переписывая с нуля.
Все данные вымышлены.

## Результат

| | До | После |
|---|---|---|
| Каталог, 50 товаров | 8,1 сек | 0,001 сек |
| Карточка товара | 0,17 сек | 0,001 сек |
| Запросов к базе на страницу каталога | 101 | 2 |
| Индексов в таблицах | 0 | 2 |

Время — по счётчику внизу страницы (PHP и база, без сети).
«До» и «после» замерены одинаково.

## Что исправлено

- **SQL-инъекции** в поиске, фильтре категорий, карточке товара и форме входа
  в админку → подготовленные запросы
- **XSS в отзывах** → экранирование всего вывода
- **Вход в админку по куке `auth=1`**, которая подделывается за секунду →
  серверные сессии с `session_regenerate_id`
- **Пароли пользователей открытым текстом** → `password_hash` / `password_verify`
- **Пароль от базы в папке сайта** → вынесен за её пределы
- **Ошибки SQL показывались посетителю** → пишутся в лог
- **Формы без защиты от подделки запросов** → CSRF-токены
- **101 запрос в цикле** → 2 запроса с JOIN
- **Ни одного индекса, MyISAM** → индексы на связях таблиц, InnoDB

Дизайн намеренно не менялся: владелец сайта должен узнать свой магазин.

## Проверить самому

Нужны PHP 8+ с mysqli и MySQL 8.

1. Создать базу: `mysql -u root < database/schema.sql`
2. Положить доступы к базе в `secrets/patient.php` двумя уровнями выше
   папки проекта:
```php
   <?php
   return ['db_host' => 'localhost', 'db_user' => 'root',
           'db_pass' => '', 'db_name' => 'patient'];
```
3. Заполнить базу: `php tools/seed.php`
4. **До:** `git checkout before`, открыть каталог, посмотреть время внизу
5. **После:** `git checkout main`,
   `mysql -u root patient < migrations/001_fix.sql`,
   `php tools/hash_passwords.php`, открыть каталог снова
